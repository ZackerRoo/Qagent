本轮按用户要求复核供应方原始调用文档，主任务先完成 Mac/云端只读请求，子任务据此实施最小客户端修正。请求结果为本轮时点证据，不代表持续稳定、业务完整覆盖或本次代码已部署。

## 文档与差异

[ProMax 原文](../promax.txt) 使用固定 HTTPS 地址、`X-API-Key` 请求头和 `requests.get(..., timeout=30)`，明确不得关闭证书校验。原文“正常 Python 请求不需要代理”不等于代码禁用环境代理；文档示例没有设置 `trust_env=False`，会沿用 requests 默认环境行为。

主任务确认云端存在 `HTTPS_PROXY`，文档调用方式请求 cashflow、`period=20241231` 返回 HTTP 200、2 行；直连路径为 `ConnectTimeout`。已有客户端显式 `trust_env=False`，会跳过该部署环境的代理。这解释了本轮观察到的一项调用方式差异，不能据此将所有历史错误都归因为代理。

基础服务文档仍只有 HTTP 地址，未向该地址发送密钥；其可验证 HTTPS 入口仍待供应方提供。

## 实施与边界

`backend/qagent/providers/tushare_relay.py` 仅将真实网络客户端改为尊重环境代理及证书环境配置；显式注入 transport 时继续隔离环境，保留 MockTransport 测试。HTTPX 按 `HTTPS_PROXY` / `NO_PROXY` 等环境配置选路。固定 HTTPS 目标、仅请求头传密钥、证书校验开启、禁止重定向与现有错误脱敏保持有效；不在配置或报告中输出代理凭据。

市场后备继续每请求 5 秒、零重试及既有批次预算。文档测试的 30 秒超时不扩展市场请求时限。研究入口原有 30 秒默认值无需修改。此改动会影响后续真正运行客户端的网络选路；本轮未修改模拟账本、冻结模型、价格质量规则或账户权限。

新增测试通过真实 HTTPX 环境路由选择配合内存 transport，覆盖 HTTPS_PROXY、NO_PROXY、固定 HTTPS/密钥头/证书校验/不重定向/5 秒参数，以及有代理环境时 MockTransport 仍隔离。相关回归和最终状态由下文补录。
