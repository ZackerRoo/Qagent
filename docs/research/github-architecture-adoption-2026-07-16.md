# GitHub 量化架构借鉴落地记录

日期：2026-07-16

## 范围

本轮参考 `bbfamily/abu`、`Jack-Cherish/quantitative` 和
`shinnytech/tqsdk-python` 的公开架构思路。Qagent 没有复制第三方交易代码，
而是把适合当前 A 股研究目标的设计重新实现为本地、可测试的领域模型。

## 已落地

### 1. 因子、策略和组合职责分离

借鉴成熟量化框架将特征计算、信号判断、组合准入和执行拆开的方式：

- `qagent/features` 保存不可变特征快照、版本、数据修订和摘要哈希。
- 全市场扫描完成全部批次后统一做横截面排名，结果不再受批次大小影响。
- `qagent/portfolio` 单独处理仓位、现金、行业、主题、ETF 重叠和市场状态约束。
- 每项组合拒绝都有可审计原因，不再把“高分”直接等同于“可以买”。

### 2. 策略生命周期与样本外准入

借鉴研究策略先观察、再验证、最后发布的治理方式：

- 策略状态为 `research / shadow / admitted / throttled / disabled`。
- 策略、因子、参数、股票池、数据修订和政策都有独立版本。
- 样本量、统计簇、置信区间、FDR、成本压力、基准超额和回撤共同决定准入。
- 软违约执行限流，硬违约执行停用或回滚，所有变化写入不可变事件记录。
- 内置策略默认进入影子验证：不显示成已验证买点，但允许模拟盘收集前向证据。

### 3. 统一事件驱动执行模型

借鉴交易系统中订单、成交、持仓和账户分层的方式：

- `qagent/execution` 定义统一的 `Order / Fill / Position / Account / MarketEvent`。
- 回测和模拟盘共用 A 股成交规则，避免两套逻辑产生不可解释偏差。
- 支持 T+1、100 股整手、价格最小变动、停牌、零成交量、一字涨跌停、跳空、
  部分成交、手续费和滑点。
- 成交事实写入事件账本，后续配置变化不会改写历史费用和成交价格。

### 4. A 股市场状态与漂移监控

- 市场状态使用带确认天数和最短停留期的状态机，压力状态可立即生效。
- 特征漂移检查覆盖缺失率、来源变化、分布 PSI、秩相关、Top-N 重合、行业集中度
  和拒绝原因变化。
- 漂移结果只产生诊断和门禁证据，不允许静默自动调权。

### 5. 后台扫描恢复

- 每个全市场批次保存候选卡、拒绝项、因子排名、策略健康和治理审计。
- 服务重启后重放已完成检查点，从下一批继续。
- 没有检查点的旧任务明确归零重跑，不保留虚假的扫描进度。
- 后台异常会写入 `failed` 状态和错误原因，不再无限显示“运行中”。

## 明确未做

- 不接券商实盘，不自动下真实订单。
- 不把历史收益或影子信号描述为未来收益保证。
- 不在分钟数据可靠性不足时伪造分钟成交。
- 不允许训练集结果直接调整正式策略权重。

## 验证

- 后端领域、API、存储迁移和恢复路径均有自动化测试。
- 前端包含策略治理契约检查、生产构建和浏览器实测。
- 实盘式模拟证据仍是负收益且样本未成熟，因此所有内置策略保持影子状态。
