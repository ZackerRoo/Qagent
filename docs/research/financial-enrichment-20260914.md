# G2-FQ1 财务质量、每日估值与业绩预告增强

日期：2026-09-14。本轮用户批准推进三类财务研究输入，沿用 G2-FQ1，不新建无界数据治理目标。当前阶段先完成最多两股、四接口的可复核观察与适配验收，再接同股票集合的隔离前向比较。获得数据不等于排名增强，更不等于正式交易权重已接入。

## 当前采集边界

`scripts/research_financial_enrichment.py` 由实现子任务开发，拟复用已存在的服务客户端及现金流研究校验，最多两只股票、每股 cashflow/income/daily_basic/forecast 四接口、每次请求 30 秒、零重试。每接口独立保留成功、空表和错误，归档原始证据与 digest；current-observation 只说明实际取得时刻可见的数据，不回填 09-11 冻结信号，不声称历史 PIT。

| 输入 | 本阶段需要核验的含义 | 不得直接推导 |
| --- | --- | --- |
| cashflow + income | 同股票、同报告期、同合并累计口径的经营现金流与总净利润/收入；非正分母和修订冲突保留原因 | 单次比率高即优质，累计值即单季或 TTM |
| daily_basic | 估值交易日、PE/PE TTM/PB 等字段原值与有限值；非正 PE 和缺数区别 | 低 PE 必然便宜，负 PE 等于上游缺失 |
| forecast | 公告日期、报告期、预告类型与数值上下界，保留重复修订及空表 | 预告等于已实现业绩，空表等于无风险或无预告 |

三类日期不能混为一个 as-of：取得时刻、估值交易日、财报期/公告日期分别记录。未来前向信号的截止时间必须晚于实际取得时刻；当日只有日期没有公告时刻的资料按保守的后续交易时点处理，不猜测盘中何时已知。若无可核验历史版本，旧报告期的当前查询仍不进入过去样本。

## 已有能力及可复用入口

代码调查确认：

1. `scripts/audit_g2_complete_cohort.py` 已能校验原始特征覆盖、缺失身份及组合；本轮继续用它区分 earnings_yield 的非正 PE 规则与真实缺数，不为提高覆盖而改冻结输入。
2. `scripts/rank_g2_consensus.py:rank_consensus` 已从 ready signal 生成固定 minimax 共识顺序，保留源 digest、股票集合、Top5/Top10/前10% 和行业分布；可作为新比较的固定基线。此函数输入仍是原两个 G2 变体，不接受本轮原始财务表。
3. `scripts/compare_g2_selections.py:compare` 已输出同日两变体的进出、重叠、Jaccard 和行业分布，可复用统计口径；它固定消费原 G2 signal，并非任意新候选排名的现成入口，不能给新数据换个旧协议名后直接传入。
4. `backend/qagent/storage/factor_research.py` 已有 `FactorShadowScore`（baseline/challenger score 和 rank）、`FactorShadowRunRef`、`FactorShadowOutcome`，以及 `record_shadow_scores`/`record_shadow_outcomes`。已有实验和候选身份校验，不另建实验库；新财务候选当前没有登记或写入这些存储。
5. `backend/qagent/research/factor_candidate_queue.py` 已区分 quality、valuation_growth_match、catalyst 等候选家族，并列出 PIT、成本与成熟样本要求；队列本身 `experiment_start_allowed=False`，仅有候选说明不能作为已开始实验的证据。
6. `backend/qagent/research/ranking_head_challenger.py:evaluate_ranking_head_challenger` 是冻结的 Top10/Top5 同一 challenger 顺序切片比较，成熟前不读收益、不完整不聚合、无自动升级。它不是任意“共识 vs 财务重排”的直接比较器；可借鉴成熟与缺样处理，不改变其冻结协议。

`backtesting/baseline_challenger.py` 依据已完成收益观察计算基线候选后验，也不是本轮四个财务表的归一化入口。因此本轮不将采集 JSON 直接接到现有交易排名或以历史收益调参后冒称前向增强。

## 最小前向对照方案与剩余接线

第一步是本轮两股语义 smoke。按接口报告有效行、日期、缺失原因及可用比率；一项失败不抹掉另外三项证据。两股样本只验证链路，不称全配对集合覆盖，遇到服务错误按零重试预算结束，不在本轮扩大到全市场抓取。

第二步在 smoke 通过后定义一个独立候选协议，固化新增特征、缺失处理、排序规则及摘要，再开始未来样本。建议先以未改动的共识排序为基线，单独研究财务质量重排，估值和预告先作为解释列；避免一次改变三类排序后无法判断来源。具体重排规则尚未冻结或实现，须在收益结果出现前确定，不能沿用旧 G2 预注册名义。用户已批准研究增强，本阶段不因此自动改正式权重。

第三步补一个独立证据拼接层：输入原 ready signal、在信号截止前取得的 enrichment 快照及新候选协议，按 instrument_id 连接，并保存原集合 digest、取得时间、源/实现/协议摘要和覆盖矩阵。主比较的基线与候选必须使用完全相同的股票 ID 集合；新字段缺失不能只从候选一侧剔除。可先规定缺失时保留基线顺序，并将共同完整子集作为附加诊断；若选择共同交集则两侧一致过滤、披露选择偏差，且不改变原冻结实验资格。实际采用哪一种须随新协议明确，当前没有偷偷设置新门禁。

第四步复用既有选股行为指标，在同集合输出基线/候选排名、Top5/Top10 进出与行业暴露，不以重叠变化替代收益。后续接 FactorResearchRepository 前需新增候选身份和协议兼容检查，确认该归档允许独立候选登记；不能写进已有两条冻结 lane 或复用其 model_digest。最小离线阶段可先独立归档比较结果，存储接线仍待实施。

第五步在事前冻结的同一入场日、观察窗口、基准和成本口径下取成熟收益，复用既有调整价格质量检查及 outcome 数据结构；未成熟、缺价、质量拒绝保留等待原因，不拿 raw 日线填充调整价。比较同日配对净超额与下行风险，同时报告覆盖、行业暴露与换手；完整案例诊断不能代替主集合结果。采用原 G2 的 20 交易日方案时须完整继承其入场/成本假设，若使用现有其他 Challenger 窗口则单列协议，不能混算。

本轮可验收交付为两股四接口的真实证据、日期/数值/缺失校验和此接线方案。候选规则冻结、全目标集合采样覆盖、排名接线、独立登记与成熟收益评价仍是后续有界步骤，未提前完成。失败结果也归档，不将研究等待扩大为所有项目停止。
