基础客户端为 `backend/qagent/providers/datahubco.py`，固定文档目标、禁止重定向、错误脱敏，只有显式 `allow_insecure_http` 才发送请求。`scripts/collect_datahubco_research.py` 通过环境密钥及 `--allow-insecure-http` 获取一个显式请求的原始表格页，记录来源、取得时间、字段、行数及摘要；不连接数据库或账户，不自动翻遍接口。原始表格的业务语义、覆盖与历史 PIT 均需逐消费者核验。

原文此前只有 HTTP 且未授权发送密钥的记录继续保留为历史。本轮新增授权更新了允许调用的边界；没有把 HTTP 描述成加密或将该授权扩展到其他服务和接收方。两服务使用独立凭据，本文不含凭据。

## 原始日线后备与发布

基础服务运行配置为 `QAGENT_DATAHUBCO_KEY`、`QAGENT_DATAHUBCO_ENABLED=true`、`QAGENT_DATAHUBCO_ALLOW_INSECURE_HTTP=true`，两个开关默认关闭；三条件齐备才构造后备。只补既有来源全部尝试后仍缺失的整只股票，不补已有股票内部日期；每次最多两只、单批、每请求 5 秒、零重试、30 秒启动预算，首次上游或结构失败停止本批并熔断 300 秒。

日线复用股票与日期身份、OHLC、重复行和有限数值校验，上海时间 15:00 前排除当日日线。成交量按手换股、成交额按千元换元，来源标识为 `datahubco_daily_raw`，调整价留空、类型 raw；不能填 G2 复权价缺口，也不提供分钟、快照或新的交易执行权限。它可影响未来日线消费者及既有日线降级估值/模拟执行，冻结模型、选股规则、账本历史和唯一账户均不改动。

ProMax 客户端的代理修正尊重 `HTTPS_PROXY`/`NO_PROXY` 等环境设置，保留固定 HTTPS、证书校验、请求头传密钥及禁止重定向；显式测试 transport 仍隔离环境。研究的文档 30 秒参数不提高运行后备的 5 秒上限。

主任务确认云端服务环境已有 `http_proxy`、`https_proxy`、`HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` 配置名称，本轮无需追加网络配置。代理值及凭据不在本文输出；存在配置仍不替代修订客户端部署后的实际选路验收。

`scripts/deploy_relay_runtime.py` 新增 `--enable-datahubco`，此模式从私密 stdin 接受两服务密钥 JSON，按明确授权配置基础服务 HTTP；不带此参数保留原 Relay 单密钥输入方式。沿用空闲检查、调度停止、writer 排空、环境原子替换、私密备份、健康检查、八表对账与失败回滚。实现和本地测试后仍须暂存 release 构建、受控切换及运行证据，不能从代码接线宣称线上已经启用。
